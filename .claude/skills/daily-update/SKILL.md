# 전력일보 갱신 절차

인자로 CSV 경로가 주어지면 그 파일을, 없으면 사용자에게 어떤 파일인지 묻는다. 여러 날짜면 **날짜 오름차순으로** 처리한다(재가동유예 판정이 직전 날짜 이력을 참조하므로 순서가 중요).

## 1. 원격 최신화 확인
```
git fetch && git log --oneline HEAD..origin/main
```
- 출력이 있으면 원격이 앞서 있는 것 → `git pull --ff-only` 후 진행. 실패(분기)하면 멈추고 사용자에게 알린다.
- 작업 트리에 커밋 안 된 변경이 있으면 무엇인지 보여주고 계속할지 묻는다.

## 2. 원본 보관
CSV를 `raw/YYYY-MM/` 폴더에 원래 파일명 그대로 복사한다(없으면 폴더 생성). 이미 같은 이름이 있고 내용이 다르면 덮어쓰기 전에 묻는다.

## 3. 파싱
```
python parse_daily_report.py raw/YYYY-MM/전력일보_YYYY.MM.DD.csv
```
같은 날짜 재파싱 시 기존 `note`는 자동 보존된다.

## 4. 검증
```
python scripts/validate_daily_data.py
```
- `✗` 오류가 있으면 **여기서 멈추고** 오류를 설명한다. 데이터를 임의로 손보지 않는다.
- `⚠` 경고 중 새로 생긴 것이 있으면 요약에 포함한다.

## 5. 요약 보고 (한국어, 짧게)
갱신한 날짜별로:
- 설비군(Crusher, R/M, K/L, Co/M, C/M) 원단위와 목표대비 % (텔레그램 알림과 같은 기준)
- `목표초과설비목록` — 특히 `검토필요: true`(목표대비 20%p 이상) 설비
- `보수상태`가 "정비중"/"재가동유예"인 설비
- 이상 징후: 생산량 0인데 사용량이 평소 수준인 설비(7/18~20 CSV 추출 오류 패턴), 전일 대비 급변
- 전체 사용량(Crusher 포함)·전력비용

이상 징후가 있으면 해당 날짜에 `note`(현장메모)를 달지 사용자에게 제안한다. note는 사용자가 동의한 문구로만 추가한다.

## 6. 커밋·푸시 (반드시 확인 후)
**push하면 GitHub Actions가 "단양공장전력관리" 텔레그램 그룹에 알림을 자동 발송한다.** 따라서 푸시 전에 반드시 사용자에게 "커밋·푸시할까요?"라고 묻고 명확한 동의를 받는다. 동의 전에는 커밋까지만 하거나 아무것도 하지 않는다.

동의하면:
```
git add daily_data.json raw/YYYY-MM/<추가한 CSV>
git commit -m "전력일보 YYYY-MM-DD 반영"
git push
```
여러 날짜면 `전력일보 YYYY-MM-DD~MM-DD 반영`. 푸시 후 대시보드 주소(https://mr1kwg-wang1.github.io/daily-power-dashboard/)를 안내한다.
